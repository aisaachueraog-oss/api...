Documentación de la API

API de Ventas

Consulta el consolidado de ventas por sucursal y año, o registra una nueva venta. La API recibe y devuelve JSON.

Base URL: http://localhost:3000/api/v1/ventas

Reemplaza localhost:3000 por el host y puerto de tu entorno. El puerto local predeterminado es 3000.

Ventas

Consultar consolidado

GET/consolidado

Obtiene el consolidado ejecutando el procedimiento db_ventas_tech.

Parámetros de consulta

ParámetroTipo esperadoRequeridoDescripción
sucursalTextoSíIdentificador o código de la sucursal reconocido por la base de datos.
anioEntero (año)SíAño para el que se solicita el consolidado.

Ejemplo de solicitud

curl "http://localhost:3000/api/v1/ventas/consolidado?sucursal=centro&anio=2025"

Respuesta correcta · 200

{
  "status": "success",
  "total_registros": 0,
  "data": []
}
Ejemplo de estructura sin resultados. Cuando hay filas, data contiene los registros con las columnas que devuelve el procedimiento almacenado. total_registros indica la cantidad de filas.
Ventas

Registrar venta

POST/

Registra una venta ejecutando el procedimiento db_registrar_venta.

Encabezados

EncabezadoValor
Content-Typeapplication/json

Cuerpo JSON

CampoTipo esperadoRequeridoDescripción
id_productoEnteroSíIdentificador del producto.
id_clienteEnteroSíIdentificador del cliente.
cantidadNúmeroSíCantidad vendida.
fecha_ventaFecha (texto)SíFecha de la venta; se recomienda el formato YYYY-MM-DD.

Ejemplo de solicitud (Windows CMD)

curl.exe -X POST "http://localhost:3000/api/v1/ventas" ^
  -H "Content-Type: application/json" ^
  -d "{\"id_producto\":12,\"id_cliente\":34,\"cantidad\":2,\"fecha_venta\":\"2025-03-08\"}"

Respuesta correcta · 201

{
  "status": "created",
  "message": "Venta registrada exitosamente",
  "datos_registrados": {
    "id_producto": 12,
    "id_cliente": 34,
    "cantidad": 2,
    "fecha_venta": "2025-03-08"
  }
}
Protocolo

Respuestas y errores

HTTPCuándo ocurreFormato
200Consulta del consolidado completada.{ "status": "success", "total_registros": n, "data": [...] }
201Venta registrada.Incluye status, message y datos_registrados.
400Faltan parámetros de consulta o campos del cuerpo.{ "error": "Bad request", "message": "..." }
500Ocurrió un error al consultar la base de datos.{ "error": "Internal Server Error", "message": "Error en MySQL" }

Las respuestas de error se envían en JSON. En la implementación actual, los errores de base de datos se responden con estado 500.

Para quien opera el servicio

Configuración del servidor

El servicio requiere Node.js, sus dependencias instaladas y acceso a una base de datos MySQL con los procedimientos almacenados utilizados por la API.

Configura estas variables de entorno antes de iniciar el servidor:

VariableUso
PORTPuerto HTTP (opcional; predeterminado 3000).
DB_HOSTHost del servidor MySQL.
DB_USERUsuario de MySQL.
DB_PASSWORDContraseña de MySQL.
DB_NAMEBase de datos.
 
npm install
node server.js
La autenticación y la validación de tipos/rangos de los campos no están implementadas por estas rutas. Usa identificadores válidos y protege el acceso al servicio en el entorno donde lo despliegues.
